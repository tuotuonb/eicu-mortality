# eICU 数据表与国内医院信息系统的对应关系

这个项目使用的是美国 eICU 多中心重症数据库（Demo 版）。它的表结构和国内医院的 HIS、LIS、电子病历高度相似。
下面这张表说明每张表"在国内医院里相当于什么"，也说明本项目的提数思路可以直接迁移到国内医院的数据上。

| eICU 表 | 内容 | 国内医院对应的系统 / 数据 |
|---|---|---|
| `patient` | 人口学信息、入出 ICU 和入出院时间、出院状态 | HIS 住院登记、病案首页 |
| `hospital` | 医院级信息：床位规模、是否教学医院、地区 | 医院主数据、多院区编码 |
| `diagnosis`、`admissionDx` | 诊断（含 ICD-9 编码）、入 ICU 诊断 | 病案首页诊断（国内用 ICD-10 国家临床版） |
| `pastHistory` | 既往史 | 电子病历（EMR）入院记录 |
| `lab` | 检验项目与结果 | LIS 检验信息系统 |
| `vitalPeriodic`、`vitalAperiodic` | 监护仪采集的生命体征 | 重症监护信息系统、护理记录 |
| `medication`、`infusiondrug` | 用药、静脉泵入药物 | HIS 医嘱、药房系统 |
| `apacheApsVar`、`apachePredVar`、`apachePatientResult` | APACHE IV 评分的输入变量和预测结果 | 重症监护信息系统的评分模块、重症质控数据 |

## 提数时的几个共通要点

1. **时间窗口以入科时间为基准**：eICU 为了脱敏，所有时间都存成"距离入 ICU 时刻的分钟数"（offset）。
   国内医院系统里存的是真实时间戳，但"入科后 24 小时内的检验值"这类需求，做法完全一样：
   先确定入科时间，再按时间窗口过滤，最后按患者聚合取首次值或最差值。
2. **一个患者可能多次入 ICU**：要先定义"住院 → ICU 入住"的层级，再决定研究单位。
   本项目只取每次住院的首次 ICU 入住，避免同一患者被重复计算。
3. **检验名称不统一**：不同医院、不同仪器的检验项目名称和单位可能不同，
   提数前要先做项目字典映射。国内多院区医院做数据整合时也是同样的问题。
4. **缺失值要区分"没测"和"测了但没记录"**：比如 APACHE 表里用 -1 表示缺失，
   提数后需要统一转成空值，并在质控报告里给出每个变量的缺失率。

## 数据合规

eICU Demo 是 PhysioNet 上的开放获取数据集（Open Database License），可以自由使用和公开分析结果。
数据已经去标识化，本项目的代码和结果中不包含任何可识别个人身份的信息。
在真实医院环境中，同样的分析应在院内数据平台上完成，遵守《个人信息保护法》和医院的数据安全管理规定。
